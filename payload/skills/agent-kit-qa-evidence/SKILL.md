# Agent Kit QA Evidence

`.agent-project-kit/AGENT-RULES.md`의 "QA 증거"와 "브라우저 작업과 사용자 도움" 규칙을 실행하는
절차다. 규칙(품질 기준 6가지·마스킹·첨부 불가 폴백)은 AGENT-RULES가 원본이며, 이 스킬은 그것을
만드는 방법만 다룬다.

## 0. 시작 전 확인

1. CONTEXT 로컬 메모의 `QA 증거 수준`과 `QA 기준 예시 링크`를 읽는다. 예시 링크가 있으면 먼저
   열어 형식을 참고하고, 이번 기능에 맞게 더 발전시킨다.
2. 쓸 수 있는 브라우저를 확인한다. **분리된 브라우저**(브라우저 자동화 도구 — 예: Playwright MCP —
   가 띄우는 별도 브라우저)만 쓴다. 사용자가 쓰고 있는 브라우저를 조작하는 도구는 쓰지 않는다.
   분리된 브라우저를 쓸 수 없으면 §6 폴백으로 간다.
3. 증거 작업 디렉터리를 새로 만든다. 저장소 작업 트리에 이미지를 두지 않는다.

   ```bash
   EVD="$(mktemp -d)"   # 보존이 필요하면 끝난 뒤 프로젝트의 로컬 QA 산출물 경로로 복사한다
   ```

## 1. 증거 수집 — 기능마다 정상 경로와 주요 실패 경로

각 단계를 다음 형식으로 기록한다(텍스트 원본은 `$EVD/steps.md`).

| 항목 | 내용 |
|---|---|
| 단계 | 번호와 이름 — "A 실행 → B 실행 → …" 순서 |
| 실행 시각 | `date -u +%Y-%m-%dT%H:%M:%SZ` (기준 시간대 명시), 경과가 근거면 기준 대비 `+Ns` |
| 명령 | 실행한 그대로(비밀값은 `<변수>`) |
| 입력 / 출력 | 코드 블록 |
| 판정 | `항목 = 값 (해석)` — 예: `status` = `409` (중복 업로드 거절, 기대와 일치) |

- **API**: 요청(메서드·URL·헤더 이름·본문)과 응답(상태 코드·본문)을 텍스트로 남긴다.
  예: `curl -sS -D "$EVD/h.txt" -o "$EVD/b.json" -w '%{http_code}\n' -X POST <URL> -H 'Authorization: Bearer <TOKEN>' --data @<file>`.
  헤더 값 중 자격증명은 저장 전에 가린다.
- **로직 주장·리뷰 반박·수정 효과**(경합·타이머·분기 등): 최소 재현 스크립트를 `$EVD/` 에 만들어
  직접 실행하고 출력·실행 시각·`항목 = 값 (해석)`·관련 기존 테스트 이름을 남긴다. 게시할 때
  **스크립트 원문을 `<details>`로** 싣는다.
- **화면**: 실제 화면을 찍는다(§3). 가공한 화면으로 대신하지 않는다.

## 2. 증거 페이지 — 화면이 없는 증거를 이미지로 만들기

백엔드·워커·스크립트처럼 화면이 없는 증거는 핵심 발췌를 HTML 페이지로 만들어 캡처한다.

- `$EVD/index.html`에 장면마다 `<section id="scene-1">…</section>`: 단계 표, 요청/응답 블록,
  수치 표, 로그 발췌. 인라인 CSS만 쓰고 외부 리소스를 불러오지 않는다. 식별자·비밀값은 여기서 가린다.
- 로컬 서버로 띄운다. **`cd` 하지 말고 `--directory`를 쓴다.** (`file://`은 자동화 도구가 막을 수 있다.)
  고정 포트는 다른 작업의 서버와 겹칠 수 있다 — 겹치면 새 서버는 바로 죽고 **다른 디렉터리를 서빙하는
  기존 서버가 대신 응답한다.** 빈 포트를 고르고, 캡처 전에 자기 페이지가 나오는지 확인한다.

  ```bash
  PORT=$(python3 -c 'import socket; s=socket.socket(); s.bind(("127.0.0.1", 0)); print(s.getsockname()[1])')
  python3 -m http.server "$PORT" --bind 127.0.0.1 --directory "$EVD" >"$EVD/server.log" 2>&1 &
  echo $! > "$EVD/server.pid"
  sleep 1; curl -sS "http://127.0.0.1:$PORT/index.html" | grep -q 'id="scene-1"' && echo "serving $EVD on $PORT"
  ```

## 3. 캡처

1. 분리된 브라우저에 **자기 탭을 새로 연다.** 다른 Agent가 같은 브라우저를 쓰고 있을 수 있다.
2. `http://127.0.0.1:$PORT/`(또는 실제 화면 URL)로 이동하고, **캡처 직전에 현재 URL을 확인한다.**
3. 요소 단위 스크린샷(예: `#scene-1`)으로 `$EVD/scene-1.png`를 만든다. 실제 화면(웹 UI·관리 UI·
   대시보드)도 같은 방식으로 찍는다.
4. 만든 이미지를 직접 열어 아래 마스킹 체크리스트를 통과하는지 본다. 통과하지 않으면 가리고
   다시 찍는다.
5. 캡처가 끝나면 로컬 서버를 끈다: `kill "$(cat "$EVD/server.pid")"`.

## 4. GitHub에 이미지 올리기 — 게시하지 않고 URL만 얻기

GitHub REST API·`gh`로는 코멘트 이미지를 올릴 수 없다. 웹 코멘트 상자의 파일 업로드만
`https://github.com/user-attachments/assets/…` URL을 만든다. 업로드한 URL은 코멘트를 게시하지
않아도 유효하다.

1. 분리된 브라우저의 **자기 탭**에서 대상 PR 페이지를 연다.
2. 로그인되어 있지 않으면(비공개 저장소가 404, 로그인 버튼 표시 등) **멈추고** 사용자에게 한 줄로
   요청한다: "분리된 브라우저 창에서 GitHub(<계정>)에 로그인해 주세요. 로그인되면 스크린샷 업로드를
   이어서 합니다." 사용자 브라우저로 우회하지 않고, 비밀번호·토큰을 대신 입력하지 않는다.
3. 현재 URL이 대상 PR인지 확인한다.
4. 페이지 하단 새 코멘트 상자의 파일 입력(`input[type=file]`, "Attach files")을 찾아, 자동화 도구의
   파일 업로드 기능(예: Playwright MCP `browser_file_upload`)으로 PNG를 올린다. 네이티브 파일 선택
   창이 열려 도구로 처리할 수 없으면 사용자 도움을 요청한다.
5. 몇 초 기다린 뒤 코멘트 textarea 값에서 이미지 태그(`<img … src="https://github.com/user-attachments/assets/…">`
   또는 `![…](https://github.com/user-attachments/assets/…)`)를 읽는다. "Uploading…" 자리표시가 남아
   있으면 더 기다린다.
6. **게시 버튼을 누르지 않는다.** textarea를 비운다(값을 비우고 입력 이벤트 발생). 페이지를 떠날 때
   저장하지 않은 변경 경고가 뜨면 버린다.

> 이 업로드 경로는 도구·GitHub UI 변경에 민감하다. 새 환경에서 처음 쓸 때 동작을 확인하고, 결과
> (로그인 유지 여부, 업로드 방식)를 CONTEXT 로컬 메모에 남긴다.

## 5. 게시와 검증

1. 본문 파일 `$EVD/body.md`를 쓴다: 기능별 절, 장면마다 캡션 한 줄(무엇을·어떤 조건에서·기대
   결과와 일치 여부) + 이미지 태그, 같은 내용의 텍스트 증거(코드 블록 — 이미지만으로 근거를 대신하지
   않는다), 재현 스크립트 원문 `<details>`, 원본 보관 경로.
2. 게시한다. 새 코멘트는 `gh pr comment <n> --body-file "$EVD/body.md"`, PR 본문 Test plan은
   `gh pr edit <n> --body-file <파일>`. 리뷰 대응이면 review-killer 코멘트 규약(라운드당 1건,
   마지막 줄 상태 마커)에 이 내용을 `### QA 증거` 절로 넣는다.
3. 검증한다. 분리된 브라우저에서 게시된 코멘트를 열고 이미지가 실제로 로드되는지 확인한다:

   ```js
   [...document.querySelectorAll('img[src*="user-attachments"]')].map(i => [i.src.slice(-16), i.naturalWidth])
   ```

   `naturalWidth`가 0인 이미지가 있으면 다시 올려 고친다(게시물 수정).
4. 자기 탭을 닫는다.

## 마스킹 체크리스트 (게시 전 필수 — 이미지와 텍스트 모두)

- [ ] 토큰·API 키·비밀번호·세션 쿠키·`Authorization` 헤더 값
- [ ] 접속 URL의 자격증명(`user:pass@host`)
- [ ] presigned URL 서명(`X-Amz-Signature`, `X-Amz-Credential`, `Signature=` 등 쿼리)
- [ ] 내부 IP·내부 호스트명
- [ ] 개인정보(이메일·이름 등)와 판정에 필요 없는 식별자
- [ ] 렌더링된 설정 출력(예: `docker compose config`)을 통째로 붙이지 않았다 — 필요한 필드만
- [ ] `<details>` 안 스크립트 원문에도 비밀값이 없다(`<변수>`로 치환)
- [ ] 이미지를 저장소에 추가하지 않았다(`git status`로 확인)

## 6. 폴백 — 분리된 브라우저를 쓸 수 없을 때

Agent 도구에 브라우저 자동화가 없거나, 로그인 요청에 답을 받을 수 없거나, 업로드가 계속 실패하면:

- 텍스트 증거(단계·실행 시각·명령·입출력·`항목 = 값 (해석)`·재현 스크립트 `<details>`)만으로
  게시하고, 본문에 `스크린샷 첨부 불가: <사유>`를 명시한다.
- 사용자 브라우저를 대신 쓰지 않는다.
- 종료 보고에서 사용자에게 첨부하지 못한 사실과 사유를 알린다.

## 7. 정리와 위임

- 로컬 서버 종료, 자기 탭 닫기, `$EVD` 보존 여부 결정(보존하면 로컬 QA 산출물 경로로 복사하고
  그 경로를 본문에 적는다). 임시 디렉터리를 지울 때는 `rm -r`을 쓴다.
- 서브에이전트에게 이 절차를 맡기면 프롬프트에 "사용자 도움이 필요하면 멈추고 질문으로 반환한다",
  "사용자 브라우저 사용 금지, 분리된 브라우저만 쓴다", "게시 전 마스킹 체크리스트 확인"을 명시한다.
