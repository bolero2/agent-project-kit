진행 중인 프로젝트(이미 Claude Code로 개발했더라도)를 킷 하네스 체계로 편입한다.
기존 자산은 **버리지 않고 재배치**하는 것이 원칙이다.

전제: `bootstrap.sh --adopt <이 프로젝트>` 가 먼저 실행되어 훅·권한 시드·스킬이 복사된 상태.
아직이면 사용자에게 먼저 실행하도록 안내하고 중단한다.

## 절차

### 0단계 — 안전 확인
- `git status`로 현재 변경을 확인한다. adopt 복사분 외의 변경이 섞여 있으면 사용자에게
  알리고 진행 여부를 확인받는다.
- 이 스킬의 모든 변경은 **커밋하지 않고 미커밋 상태로 남긴다** — 최종 검토 후 커밋은
  사용자 승인으로만 한다 (롤백 = `git restore` + 생성 파일 삭제).

### 1단계 — 기존 CLAUDE.md 재편 (핵심)
- 기존 CLAUDE.md를 전부 읽고 시드 구조로 재배치한다:
  - **§0 RULE 삽입**: 킷 시드의 §0(= claude-md-init 스킬 스켈레톤의 §0과 동일본)을
    문서 최상단에 그대로 넣는다. 기존 문서에 §0과 **충돌하는 규칙**(보고 방식, 커밋
    규칙 등)이 있으면 지우지 말고 충돌 목록을 사용자에게 보여주고 어느 쪽을 따를지
    결정받는다. 결정된 내용은 §0-3 원칙대로 그 자리에서 반영한다.
  - **기존 내용은 §1~9로 재배치**: §1 개요 / §2 구조 / §3 핵심 결정&근거 / §4 실행법 /
    §5 데이터·산출물·보안 / §6 외부 문서 / §7 지뢰 / §8 완료·TODO / §9 환경.
    분류가 애매한 내용은 가장 가까운 장 하단에 **원문 그대로** 옮긴다(요약으로 정보를
    잃지 않는다).
- repo 탐색(구조, 빌드/실행/테스트 명령, 데이터 경로 — 실제 확인된 것만)으로 빈 장을
  보강한다. 모르는 것은 지어내지 말고 `TBD`.
- `git log`를 훑어 §3(핵심 결정)과 §8(완료/미완료) 후보를 뽑고, 사용자 확인을 받아
  채운다. 추측으로 결정 이력을 창작하지 않는다.

### 2단계 — settings.json 병합
- `.claude/settings.json`이 adopt가 복사한 킷 시드 그대로라면 그대로 둔다.
- 프로젝트에 **원래 settings.json이 있었다면**(no-clobber로 킷 시드가 스킵된 경우):
  킷 시드의 `permissions.deny` 전체와 `hooks`(PreToolUse/Stop)를 기존 JSON에 병합한다.
  기존 allow/deny/훅 항목은 보존하고, 병합 후 `python3 -m json.tool`로 유효성을 확인한다.
- 이 프로젝트에서 자주 쓰는 읽기 전용 명령이 있으면 allow 추가를 제안한다
  (그간의 승인 마찰을 줄이는 목적).

### 3단계 — 보안 대조 (§0-4)
- §5에 기록한 민감 경로가 `.gitignore`와 settings `deny` **양쪽에서** 실제로 막히는지
  대조한다. --adopt가 범용 보안 패턴은 append했지만, 프로젝트 고유 데이터 경로
  (데이터셋·모델·산출물 등)는 여기서 추가한다.
- `git ls-files`로 이미 추적 중인 민감 파일이 없는지 확인하고, 있으면 사용자에게 보고한다
  (히스토리 정리는 별도 결정 사항 — 임의로 하지 않는다).

### 4단계 — 마무리
- 변경 요약 보고: 재편된 CLAUDE.md 목차, 충돌 해결 내역, settings 병합 결과, TBD 목록.
- `docs/change-log/YYYY-MM-DD.md`에 편입 기록을 작성한다(전제·실행 명령 포함).
- 사용자 검토 후 커밋을 제안한다. 훅 활성화로 이후 에이전트가 `rm -rf`·force push를
  쓸 수 없게 됨을 안내한다.
