세션(또는 마일스톤)을 하네스 규칙(§0-3, GETTING-STARTED Phase 3)대로 마감한다.
전 과정에서 실측값만 기록한다(§0-1) — 성공만 골라 적지 않는다.

## 절차

### 1. 이 세션의 작업 사실 수집
- `git log`(이 세션에서 만든 커밋)·`git status`·대화 내용에서 실제로 한 일을 정리한다.
- 실패한 것, 미완으로 남은 것, 되돌린 결정도 있는 그대로 수집한다.

### 2. CLAUDE.md 현행화 (§0-3)
- CLAUDE.md가 아직 시드 상태(⚙️ 시드 마커 잔존 또는 §1~9가 TBD)면 이 단계는 생략하고
  그 사실만 보고한다 (킷 저장소 자신이 이 경우에 해당).
- **§8 완료/미완료(TODO)**: 이번에 끝낸 항목 이동, 새로 생긴 TODO 추가.
- 이번 세션에 해당 사항이 있을 때만:
  - 주요 결정 확정/번복 → §3에 무엇을/왜(실측 근거)/언제.
  - 실측으로 기존 기록이 반증됨 → 지우지 말고 "정정(날짜): ..." 형식으로.
  - 새로 밟은 지뢰 → §7. 스코프 변경 → §1. 실행법 변경 → §4(실행해 본 명령만).
- 해당 없는 장은 건드리지 않는다.

### 3. change-log 기록
- `docs/change-log/YYYY-MM-DD.md`에 항목 추가(파일 없으면 생성 + README 인덱스에 링크).
- §0-2 요건 충족: ①전제(커밋 해시) ②실행 명령(실제 실행한 것만) ③출력 해석 ④검증 앵커.
- 미해결 이슈는 "이슈/논의" 섹션에.

### 4. 범용 패턴 역수출 점검
- 이번 세션에서 확립된 것 중 **프로젝트-무관 범용** 패턴(규칙, 절차, 훅, 스킬)이
  있는지 검토한다.
- 있으면 "킷(claude-project-kit) 반영 후보" 목록으로 사용자에게 보고만 한다 —
  실제 반영은 사용자 승인 후 킷 저장소에서 한다.

### 5. 반복 지시 점검
- 이 세션에서 같은 지시를 2회 이상 받은 작업이 있으면 스킬화 후보로 보고한다
  (절차: `.claude/skills/_template` 복사 → `SKILL.template.md`를 `SKILL.md`로 개명).

### 6. 커밋 제안
- 위에서 갱신한 CLAUDE.md·change-log를 포함한 커밋을 제안한다.
- 커밋·푸시는 사용자 승인으로만 한다. 완료 후 `bootstrap.sh --doctor` 점검을 권한다.
