새 프로젝트의 CLAUDE.md를 만든다. 아래 절차를 순서대로 수행하라.

## 절차

### 1단계 — 저장소 탐색 (탐색 가능한 사실만)
repo를 탐색해 다음을 **실제로 확인된 것만** 수집한다 (추측 금지, 없으면 "TBD"):
- 디렉토리 구조, 주요 모듈/진입점, 언어/프레임워크
- 빌드/실행/테스트 명령 (package.json, Makefile, docker-compose, README 등에서)
- git 원격/브랜치, 기존 문서(README, docs/)
- 데이터/모델/산출물 디렉토리와 .gitignore 상태

### 2단계 — 사용자 인터뷰 (탐색 불가능한 것)
AskUserQuestion으로 다음을 묻는다 (이미 대화에서 알려진 것은 건너뜀):
1. **이 프로젝트는 무엇인가** — 목표 한 문장, 발주처/이해관계자, 성공 기준
2. **제약** — 마감, 타깃 환경(엣지/서버/클라우드), 성능 요구치
3. **보안/민감정보** — 외부 유출 금지 대상(데이터, 얼굴, 키), 푸시 금지 항목
4. **외부 문서** — Confluence/Notion/Jira 등 연결할 문서 위치

### 3단계 — CLAUDE.md 작성
아래 스켈레톤으로 작성한다. **0장 RULE은 그대로 복사(변형 금지)**, 나머지는 1·2단계 결과로 채운다.
모르는 항목은 지어내지 말고 `TBD`로 남긴다.

```markdown
# CLAUDE.md — <프로젝트명> 인수인계

> 새 세션을 위한 전체 컨텍스트. 작업 전 이 문서를 먼저 읽을 것.

## 0. ⚡ 작업 원칙 (RULE — 최우선, 절대 위반 금지)

### 0-1. 정직성: 실측값만 보고
- 거짓말 금지. 추정·추론 금지. 상상 금지. 가정 금지.
- 허구·허위사실 기반 작업·보고·공유 금지.
- "~될 것 같아서, ~될 것이다" 같은 불확실한 사실에 근거하지 않기.
- 보고하는 모든 수치는 이 세션의 실행 로그에 있는 실측값만. 되면 된다고, 안 되면 안 된다고 보고.
- 예측이 꼭 필요하면 반드시 "미측정/추정"을 명시. "검증했다"는 말은 해당 축을 분리해 실제 확인한 경우에만.

### 0-2. 문서·보고서: 인간이 재현 가능한 실행 명령어 필수
- 문서·보고서 작성 시 "인간이 직접 재현 가능하게끔 관련 실행 명령어 기재"를 꼭, 반드시 할 것.
- 매 문서에 포함: ①전제(커밋 해시·이미지·데이터 경로) ②실행 명령(복사→실행 가능한 전체 커맨드) ③출력 해석 ④검증 앵커(정상 기준 수치).
- 명령어는 실제로 실행해 본 것만 기재. 에이전트 위임 시에도 이 요건을 프롬프트에 명시.

### 0-3. 이 문서의 갱신 (living document)
- 다음 시점에 **즉시 이 문서를 갱신**한다: 주요 결정 확정/번복, 실측으로 기존 기록 반증,
  지뢰(함정) 발견, 스코프 변경, 마일스톤 완료.
- 틀린 기록은 지우지 말고 "정정(날짜): ~는 틀렸다, 실측 결과 ~" 형태로 남긴다(같은 실수 방지).
- 세션 종료 시 §완료/미완료(TODO)를 현행화한다.

## 1. 프로젝트 개요
(목표 한 문장 / 발주처·이해관계자 / 요구사항 출처 / 성공 기준)

## 2. 저장소 구조
(디렉토리 표 + 핵심 모듈 설명)

## 3. 핵심 결정 & 근거
(결정마다: 무엇을 / 왜(실측 근거) / 언제. 반증되면 정정 기록)

## 4. 실행 방법
(빌드·실행·테스트 — 실제 실행해 본 명령만)

## 5. 데이터 / 산출물 / 보안
(경로 표 + gitignore 여부 + ⚠️외부 유출 금지 대상 명시)

## 6. 외부 문서 맵
(Confluence/Jira 등 ID·링크)

## 7. ⚠️ 지뢰 / 주의사항
(밟아본 함정만 — 발견 즉시 추가)

## 8. 완료 / 미완료(TODO)

## 9. 환경
(OS, 언어 버전, GPU, 도구 버전, git 계정)
```

### 4단계 — 마무리
- 작성한 CLAUDE.md를 사용자에게 요약 보고 (TBD로 남은 항목 명시)
- git repo면 커밋 제안 (푸시는 사용자 확인 후)
