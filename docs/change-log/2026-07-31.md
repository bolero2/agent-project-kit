## [ADD] 커스텀 Agent 2종 + AGENT-RULES 공통 계약 + manifest schema v3 (kit 1.2.0)

사용자 요구사항(Agent 생성·동작 규칙, Review Killer, developer) 검토 후 확정된 설계로 구현.

- **`AGENT-RULES.md`** (local-only, `.agent-project-kit/`): 모든 커스텀 Agent의 공통 계약 —
  트리거 문구로만 가동(자동 가동 없음), 계층적 문서 정독(필수 문서 → recursive 목록 →
  관련 문서만 추가 정독), 모호하면 질문하고 답을 받을 때까지 보류, 명시된 작업 범위만 수정,
  soln-va-tools 스킬 우선, 한 커밋 = 하나의 변경 이유 + 코드 + 테스트, force-push 절대 금지,
  conflict는 merge 우선(정말 불가능할 때만 rebase, force-push는 그때도 금지), 자체 merge
  금지("머지 가능합니다" 통보), 브랜치·커밋·PR 제목에 Jira 번호 금지(description 링크 허용),
  API 신규/변경/삭제는 PR description 필수 기재, QA 규칙(docker+Playwright / pytest 필수 /
  없으면 질문 후 CONTEXT 기록), `<파일>.lock` 규약, "상위 모델로 재가동하세요" 정책,
  중간 산출물은 작업 채널·최종만 보고.
- **`review-killer` Agent**: `REVIEW_AUTO_PROCESS.md`(사용자의 실전 검증 프로세스, 2026-07-30~31
  dataforge 세션)를 일반화 — 가동 전 기존 리뷰 sweep, conflict 선처리, 30초×40~60회 폴링 +
  blocker(mergeable/CI/워크플로) 동시 감시, Blocker/Major 위주 수정/반박/보류, 상태 마커 기반
  재가동, 상태 기반 종료(수렴/approve — 거짓 수렴 금지, 판정 근거 필수). 리뷰봇 식별자·QA
  방법 같은 프로젝트 특화 값은 CONTEXT 로컬 메모로 분리.
- **`developer` Agent**: Jira 보드/담당자 기반 티켓 선정(미지정 시 CONTEXT 기억값, 그것도
  없으면 질문), 티켓 잠금 코멘트와 타 Agent 양보, 범위 제한, docker rebuild/run + Playwright
  QA, **commit/PR 승인 게이트**(초안 제시 후 사용자 승인까지 대기 — 응답이 늦어도 임의 진행
  금지), 완료 시 잠금 삭제·이동 목적지 질문.
- **schema v3**: `SCHEMA_AGENTS` 동결, `payload/agents/<name>/AGENT.md` 한 벌을
  `.claude/agents/<name>.md`(그대로, model: opus)와 `.codex/agents/<name>.toml`(설치 시 렌더링,
  model: gpt-5.6-sol / reasoning high / sandbox workspace-write, `developer_instructions`에 동일
  본문)로 배포. Codex 커스텀 Agent 경로·필드는 공식 문서(learn.chatgpt.com subagents)로 확인.
  v1/v2 설치본은 기존 업그레이드 경로로 재설치 시 exclude block만 교체된다. `KIT_VERSION`
  1.1.0 → 1.2.0.
- CONTEXT.md: 커스텀 Agent 절, lock 규약, 로컬 메모 필드(QA 방법·리뷰봇 식별자·Jira 보드/담당자)
