## [ADD] --lite 모드 — non-git 폴더용 라이트 설치 (kit 1.5.0)

- 배경: "하네스를 꼭 git repository에만 적용해야 하나"라는 사용자 질문에서 출발. 검토 결론 —
  격리 4중 방어는 Git 위에서만 성립하므로 기본 설치는 Git 필수 유지, 대신 스킬·Agent·상태
  파일은 git 독립적이므로 격리 보호를 뺀 라이트 모드를 별도 제공.
- 동작:
  - `bootstrap.sh --lite <폴더>`: non-git 폴더에 payload 전체(스킬 7종·Agent 2종·CONTEXT/
    HANDOFF/AGENT-RULES/템플릿/config seed·provider hook 설정)를 설치. exclude/Git hook/
    common-dir 원장은 설치하지 않음. manifest는 `.agent-project-kit/manifest.json`
    (install_mode "lite", 폴더 절대경로 기록, allowlist·hash는 schema 동결값으로 검증).
  - CONTEXT 상단에 "LITE — Git 격리 보호 없음, git init 시 commit 전에 --uninstall 후 정식
    전환" 경고 배너를 설치 시 렌더링(mutable이라 이후 사용자 편집 보존).
  - doctor/diff/uninstall이 lite 원장을 자동 인식. 재설치 멱등(mutable 보존, 수정된 immutable
    충돌 중단), uninstall은 보수 정책 동일(수정본 있으면 전체 중단) + 부산물 제거.
  - **git init 전환 안전장치**: doctor가 전환을 감지하면 ERROR로 정식 재설치를 강제 안내,
    lite 원장이 있는 폴더의 정식 install/adopt는 --uninstall 선행을 요구, 전환 후 uninstall은
    tracked 킷 파일이 있으면 중단. Git 저장소에는 --lite 거부.
- 검증:

```bash
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s tests
# Ran 90 tests in 100.708s — OK (86 + lite 4: 왕복/뮤터블 보존·보호/모드 상호 거부/git 전환)
```

  E2E 실측: lite 설치→배너 확인→멱등 재설치→doctor OK→git init 후 doctor exit 1(전환 감지)
  →uninstall→정식 설치 전환→doctor OK.
- 한계(정직): lite에는 exclude·pre-commit/pre-push guard가 없다 — git init 후 전환 전에
  commit하면 킷 파일이 새어 나갈 수 있으며, 방어는 CONTEXT 배너(프롬프트)와 doctor(실행 시)
  뿐이다. `KIT_VERSION` 1.4.1 → 1.5.0.
