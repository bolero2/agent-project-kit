## [ADD] reviewer Agent — PR 리뷰 자동 수행 (kit 1.6.0, schema v6)

- 배경: 킷에는 리뷰 **대응** 측(`review-killer`)만 있고 리뷰 **수행** 측이 없었다. 사용자는
  Claude로 작업하면 Codex에, Codex로 작업하면 Claude에 리뷰를 요청하는 운용을 이미 하고
  있었고(수동 프롬프트), 그 요청 패턴을 Agent로 고정해 두 세션이 사람 개입 없이 티키타카하며
  머지 가능 상태로 수렴시키는 것이 목표.
- 동작 (`payload/agents/reviewer/AGENT.md`):
  - 트리거: "이 PR 리뷰하고 결과는 각 PR의 코멘트로 작성하라", "재리뷰 진행해". PR URL/번호를
    여러 개 받으면 각각을 개별 리뷰하고 각 PR에 코멘트를 남긴다(타 저장소는 `--repo`).
  - **읽기 전용**: 코드 수정·commit·push·브랜치 생성·merge·approve 금지, checkout 없이
    `gh pr diff`/`gh pr view`/파일 읽기로만 검토. 수정은 대응 측의 몫.
  - 게시 형식: 라운드당 PR 이슈 코멘트 1건(Blocker/Major/Minor + 이전 지적 처리 현황 표),
    마지막 줄에 상태 마커 `<!-- reviewer-state: round=N; head=<sha>; blocker=n; major=n;
    verdict=pending|converged -->`. 인라인 라인 코멘트는 쓰지 않는다 — 대응 측의 "코멘트 개수
    증가" 폴링 신호를 흐리기 때문.
  - 폴링: 30초×40~60회 blocking 스크립트 1회 호출. 신호는 **head sha 변경**(신규 커밋) 또는
    **자기 마커가 없는 코멘트 증가**(반박·보류) 중 먼저 오는 쪽. 커밋만 감시하면 대응 측이
    반박만 하고 커밋을 안 할 때 교착되므로 둘 다 본다. PR 여러 개를 한 루프에서 감시.
  - 재리뷰: 마커의 `head`와 현재 `headRefOid`로 증분 diff(`gh api .../compare/A...B`)를 얻고,
    이전 Blocker/Major를 해소/반박 수용/반박 거절/보류 수용으로 하나씩 판정한다. "고쳤다"는
    코멘트를 믿지 않고 파일을 읽어 확인한다.
  - 종료: 새 Blocker/Major 없음 + 이전 지적 전부 닫힘 → `verdict=converged` + "머지 가능합니다".
    같은 지적을 2회 재요청해도 미해소면 수렴을 가장하지 않고 "미해소"로 명시하고 종료.
  - 지적 품질 규칙: `파일:라인` 근거 필수(diff 문맥 추정 금지), PR 범위 밖은 Info만, 취향은
    Major 금지, 문제가 없으면 없다고 쓰기(지적 수 채우기 금지).
- 상호운용: `review-killer`에 "상대가 킷 reviewer면 식별자는 `<!-- reviewer-state: ... -->`,
  `verdict=converged`가 머지 OK 신호"를 명시. CONTEXT의 `리뷰봇 식별자` 메모에도 같은 힌트.
- schema: `SCHEMA_AGENTS[6] = (developer, review-killer, reviewer)`. v5까지의 allowlist는 그대로
  동결해 구버전 원장의 검증·업그레이드·제거 경로를 유지. `KIT_VERSION` 1.5.0 → 1.6.0.
- 검증:

```bash

# Ran 92 tests in 107.649s — OK (84 → 92: v5→v6 업그레이드/직접 제거 2건 + AGENT_NAMES
# 파라미터화 테스트에 reviewer 추가분)
```

- 미실행(정직): reviewer Agent의 실제 PR 가동과 review-killer ↔ reviewer 짝짓기 실측은
  하지 않았다. 수용 테스트 시나리오 K·L을 `docs/acceptance-test.md`에 추가만 해 둔 상태다.

  `payload/runtime/CONTEXT.md`, `payload/runtime/AGENT-RULES.md`,

## [FIX] 리뷰 짝 Agent — 머지 판정 혼동·1라운드 중단·코멘트 신호 결함 (kit 1.7.0)

- 배경: `reviewer`를 실제 PR(#216)에 붙인 결과 3가지 결함이 실측되었다.
  1. 최종 보고에 "판정: pending / 상태: MERGEABLE / CLEAN"이 함께 나와 **미해소 지적 5건이
     있는데도 머지 가능처럼 읽혔다.** GitHub의 `mergeable`은 "충돌 없음"이라는 기계 신호인데
     본문이 그것을 blocker 감시용으로만 쓰라고 하고 보고 어휘를 분리하지 않았다.
  2. 리뷰 1회만 수행하고 사용자에게 보고하며 종료했다. 폴링 규칙이 있었지만 종료 조건이
     화이트리스트가 아니어서 "타임아웃 시 종료"가 조기 종료의 근거로 쓰였다.
  3. 두 Agent가 상대를 깨우는 신호가 코멘트라는 점이 규약으로 못박히지 않아, 커밋마다 또는
     리뷰마다 코멘트 수가 흔들릴 여지가 있었다.
- 수정 (`payload/agents/reviewer/AGENT.md`, `payload/agents/review-killer/AGENT.md`):
  - **머지 어휘 분리**: `mergeable=MERGEABLE`/`CLEAN`은 "머지 충돌 없음"으로만 표기하고 리뷰
    판정 자리에 쓰는 것을 금지. 판정 어휘는 `Verdict: changes requested (...)` /
    `Verdict: no blocking findings — ready to merge` 두 가지로 고정.
  - **ready to merge 체크리스트 7개** 신설: 지적 0건 / CI green / 변경 동작의 테스트 존재·통과 /
    계약(API·스키마·설정) 호환성·마이그레이션·문서 / 보안·데이터 경계 / 대응 측 QA 근거 /
    머지 충돌 없음(필요조건일 뿐). "확인하지 못했다"를 "문제 없다"로 바꿔 쓰는 것을 명시 금지.
  - **완주 규칙**: 종료 허용 조건을 3가지 화이트리스트로 고정(머지 OK 판정 / 무한 루프 수렴 —
    같은 지적 3라운드, 미해소 명시 / 컨텍스트 한도 — HANDOFF 후 재가동 요청). 폴링 사이클을
    30초×30회(15분)로 바꾸고 **무변화 종료(`NO_CHANGE`)는 종료 사유가 아니라 재진입 사유**로
    명문화. 상한 없이 세션이 사는 동안 완주.
  - **라운드당 코멘트 정확히 1건**: 리뷰 측은 리뷰를 쪼개지 않고, 대응 측은 커밋·push를 몇 번
    하든 push 완료 후 1건만. 지적/커밋이 없는 라운드에도 코멘트는 남긴다(침묵 = 교착).
  - **코멘트 중립화**: 제목에서 Agent 이름 제거 → `## 🔍 Code Review — round N` /
    `## 🛠 Review Response — round N`. 상태 마커도 `reviewer-state` → `pr-review-state`,
    `review-killer-state` → `pr-review-reply-state`. 구버전 마커도 상대 식별에는 인정한다.
- schema 영향 없음(배포 파일 목록 불변, v6 유지). `KIT_VERSION` 1.6.0 → 1.7.0.
- 검증:

```bash
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s tests
# Ran 95 tests in 105.251s — OK (92 + 짝 계약 3: 맞물리는 중립 마커 / GitHub 상태와 판정 분리 /
# 완주 규칙과 코멘트 1건 규약)
```

- 미실행(정직): 수정본으로 실제 PR을 다시 돌린 재검증은 하지 않았다. 시나리오 K·L 실측은 여전히
  미완이며, 특히 "15분 무변화 후 재진입"과 "1라운드 조기 종료 재발 여부"가 확인 대상이다.
- 양쪽 세션의 킷 버전이 다르면 마커가 어긋난다. 짝짓기 운용 전 양쪽 다 1.7.0 이상으로 재설치.
