## [ADD] reviewer Agent — PR 리뷰 자동 수행 (kit 1.6.0, schema v6)

- 배경: 킷에는 리뷰 **대응** 측(`review-killer`)만 있고 리뷰 **수행** 측이 없었다. 사용자는
  Claude로 작업하면 Codex에, Codex로 작업하면 Claude에 리뷰를 요청하는 운용을 이미 하고
  있었고(수동 프롬프트), 그 요청 패턴을 Agent로 고정해 두 세션이 사람 개입 없이 티키타카하며
  머지 가능 상태로 수렴시키는 것이 목표.
- 동작 (`payload/agents/reviewer/AGENT.md`):
  - 트리거: "이 PR 리뷰하고 결과는 각 PR의 코멘트로 작성하라", "재리뷰 진행해". PR URL/번호를
    여러 개 받으면 각각을 개별 리뷰하고 각 PR에 코멘트를 남긴다(타 저장소는 `--repo`).
  - **읽기 전용**: 코드 수정·commit·push·브랜치 생성·merge·approve 금지, checkout 없이
    `gh pr diff`/`gh pr view`/파일 읽기로만 검토. 수정은 대응 측의 몫.
  - 게시 형식: 라운드당 PR 이슈 코멘트 1건(Blocker/Major/Minor + 이전 지적 처리 현황 표),
    마지막 줄에 상태 마커 `<!-- reviewer-state: round=N; head=<sha>; blocker=n; major=n;
    verdict=pending|converged -->`. 인라인 라인 코멘트는 쓰지 않는다 — 대응 측의 "코멘트 개수
    증가" 폴링 신호를 흐리기 때문.
  - 폴링: 30초×40~60회 blocking 스크립트 1회 호출. 신호는 **head sha 변경**(신규 커밋) 또는
    **자기 마커가 없는 코멘트 증가**(반박·보류) 중 먼저 오는 쪽. 커밋만 감시하면 대응 측이
    반박만 하고 커밋을 안 할 때 교착되므로 둘 다 본다. PR 여러 개를 한 루프에서 감시.
  - 재리뷰: 마커의 `head`와 현재 `headRefOid`로 증분 diff(`gh api .../compare/A...B`)를 얻고,
    이전 Blocker/Major를 해소/반박 수용/반박 거절/보류 수용으로 하나씩 판정한다. "고쳤다"는
    코멘트를 믿지 않고 파일을 읽어 확인한다.
  - 종료: 새 Blocker/Major 없음 + 이전 지적 전부 닫힘 → `verdict=converged` + "머지 가능합니다".
    같은 지적을 2회 재요청해도 미해소면 수렴을 가장하지 않고 "미해소"로 명시하고 종료.
  - 지적 품질 규칙: `파일:라인` 근거 필수(diff 문맥 추정 금지), PR 범위 밖은 Info만, 취향은
    Major 금지, 문제가 없으면 없다고 쓰기(지적 수 채우기 금지).
- 상호운용: `review-killer`에 "상대가 킷 reviewer면 식별자는 `<!-- reviewer-state: ... -->`,
  `verdict=converged`가 머지 OK 신호"를 명시. CONTEXT의 `리뷰봇 식별자` 메모에도 같은 힌트.
- schema: `SCHEMA_AGENTS[6] = (developer, review-killer, reviewer)`. v5까지의 allowlist는 그대로
  동결해 구버전 원장의 검증·업그레이드·제거 경로를 유지. `KIT_VERSION` 1.5.0 → 1.6.0.
