## [UPDATE] QA 증거 규칙 + 브라우저 작업과 사용자 도움 (kit 1.7.1)

- 배경: PR의 QA가 텍스트 주장("테스트했다")뿐이라 리뷰어가 확인할 수 없었고, 리뷰가
  "실환경 검증 미확인"을 라운드마다 반복했다. 또 브라우저 자동화가 로그인되지 않은 상태로
  비공개 페이지 404를 만나고도 사용자에게 알리지 않은 채 진행한 일이 있었다.
- `payload/runtime/AGENT-RULES.md`
  - QA 규칙을 `검증 방법` / `QA 증거` 두 절로 나눴다. "어느 것에도 해당하지 않으면" 문장이
    docker·Python 조건 바로 뒤에 오도록 정리해, 새 항목이 끼어들어도 가리키는 대상이 흐려지지
    않게 했다.
  - `QA 증거`: PR 생성 시 항상 수정 기능 QA + 증거 첨부(정상·주요 실패 경로), 리뷰 대응에서
    QA를 근거로 쓰거나 실환경 검증을 요구받을 때도 첨부. 품질 기준 5가지(실제 화면 캡처 /
    API 요청·응답을 텍스트와 이미지 둘 다 / 재현 명령 + `항목 = 값 (해석)` / 흐름 테스트의
    순서·단계별 입출력 / 단계별 실행 시각과 `+Ns`), 게시 전 마스킹, 이미지 커밋 금지,
    도구·환경이 첨부를 못 하면 `스크린샷 첨부 불가: <사유>` 폴백(브라우저 없는 도구 포함).
  - 신규 절 `브라우저 작업과 사용자 도움`: Agent의 브라우저 작업은 **분리된 브라우저에서만**
    (자동화 도구가 띄우는 별도 브라우저), 사용자 브라우저를 조작하는 도구는 쓰지 않는다
    (사용자 작업 방해, 로그인·탭·개인 데이터 혼입). 자동화 설정을 사용자 프로필·확장을
    쓰게 바꾸지 않는다. 로그인·2FA·CAPTCHA·SSO 동의·연결 끊김·네이티브 대화상자·인증성
    404/403이면 즉시 무엇이 필요한지와 다음 할 일을 말하고 기다린다(분리된 브라우저 창에
    로그인 요청, 사용자 브라우저로 우회 금지, 비밀번호·토큰 대리 입력 금지). 서브에이전트
    프롬프트에 "멈추고 질문으로 반환"과 "사용자 브라우저 사용 금지"를 명시.
