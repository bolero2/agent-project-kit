## [FIX] guard agent_hook이 커밋 대상이 아니라 세션 cwd 저장소를 검사하던 결함 (kit 1.10.0)

- 배경(실측 결함): `agent_hook()`은 hook payload의 `cwd`로 저장소를 정했다. 그래서
  1. 킷을 설치한 작업 셸 아래의 **manifest 없는 별도 저장소**로 세션 cwd가 들어가면
     "킷 manifest를 검증할 수 없음"으로 **모든 `git commit`이 차단**됐다(공용 저장소라 킷 파일을
     심을 수도 없다).
  2. 반대로 셸 루트에서 `git -C <다른 저장소> commit`을 하면 **엉뚱한(셸 루트) 저장소의 staged**를
     검사해, 대상 저장소의 secret이 검사 없이 통과했다.
  3. 세션 cwd가 유지되지 않는 서브에이전트는 1의 회피책(셸 루트 + `git -C`)조차 쓸 수 없었다.
- 수정 (`payload/hooks/guard.py`):
  - 명령의 각 `git … commit`마다 git 전역 옵션을 해석해 대상 저장소를 구한다: `-C`(누적·상대 경로),
    `--git-dir`/`--work-tree`(해석한 git dir이 그 work tree에서 발견되는 git dir과 같을 때만 —
    분리 구성은 "검사할 수 없음"으로 차단), `-c`/`--no-pager` 등 옵션 건너뛰기. 변수·명령 치환
    (`$`, 백틱)이 든 경로는 해석하지 않고 차단한다.
  - 대상이 **킷 관리 저장소**(manifest가 있거나, 이 guard 사본이 들어 있는 저장소)면 기존 검사 그대로
    (킷 소유 경로 + 민감 파일명 + secret 패턴, manifest가 없어지면 차단). 그 외 manifest 없는
    저장소는 **일반 검사만**(민감 파일명 + secret 패턴).
  - Stop 이벤트도 같은 판정을 쓴다(cwd가 manifest 없는 저장소여도 막지 않음, 일반 검사는 수행).
  - `git push`는 원래 agent hook의 staged 검사 대상이 아니었다(파괴적 push 차단만). 변경 없음 —
    킷 관리 저장소의 push는 Git pre-push guard가 계속 담당한다.
- 한계(정직): PreToolUse 시점 검사이므로 `git add x && git commit`처럼 같은 명령 안에서 뒤늦게
  stage되는 파일은 보지 못한다(기존과 같음). manifest 없는 저장소에는 Git pre-commit guard가 없으므로
  이 경우의 방어는 agent hook 한 겹뿐이다.
