    도구·환경이 첨부를 못 하면 `스크린샷 첨부 불가: <사유>` 폴백(브라우저 없는 도구 포함).

## [FIX] 폴링 사이클이 도구 timeout을 넘고 신호가 마커 필터에 묶인 결함 (kit 1.7.2)

- 배경(실측 결함 2건):
  1. 30초 × 30회(약 15분) 사이클을 한 번의 blocking 호출로 돌리면 호스트 도구의 명령 timeout
     (예: Claude Code Bash 도구 호출당 최대 600초)을 넘는다. 호출이 강제 종료되면 그 사이의
     감지 결과와 출력을 통째로 잃는다. 19회처럼 상한에 붙여 잡아도 API 호출 오버헤드가 얹혀 넘는다.
  2. review-killer는 리뷰봇 마커가 들어간 코멘트만 셌다. 리뷰가 사람 계정·마커 없는 코멘트·
     라인 코멘트만 있는 review로 올라오면 필터된 개수가 영원히 0이라 폴링이 헛돌았다.
- 수정:
  - `payload/runtime/AGENT-RULES.md` 대기·폴링: 한 번의 blocking 호출은 도구의 명령 timeout
    안에 끝나야 한다는 원칙(도구 중립 — 예시로 Claude Code 600초), 사이클 약 9분 이하·기본
    30초 × 15회, 사이클 사이에 turn을 끝내지 않고 다음 호출로 이어감.
  - `payload/agents/review-killer/AGENT.md`: 골격을 30초 × 15회로, 신호를 PR issue 코멘트 +
    review 코멘트 + review 제출의 **전체 개수 증가**로 바꾸고(증가 감지 후 분류), 매 회차
    `mergeable`/`mergeStateStatus`와 `gh pr checks`의 실패 증가를 blocker로 감시.
  - `payload/agents/reviewer/AGENT.md`: 같은 사이클 원칙, 스냅샷을 head sha + 충돌 상태 + CI
    bucket 요약 + 전체 개수로 확장(자기 마커 필터 제거 — 기준값은 자기 코멘트 게시 뒤에 잡는다).
  - README·GETTING-STARTED·acceptance-test의 "30초×30회(15분)" 서술을 갱신.
- 검증: 골격의 `gh`/`jq` 식은 실제 공개 PR 하나에 읽기 전용으로 실행해 합계·CI bucket 요약·
  충돌 상태가 나오는 것을 확인했다(zsh). 테스트는 두 골격을 추출해 `bash -n` 구문 검사,

## [UPDATE] review-killer 외부 리뷰봇 모드 (kit 1.8.0)

- 배경: review-killer는 상대가 킷 `reviewer`처럼 `verdict=ready`·approve를 내는 것을 전제로
  했다. 실사용에서는 GitHub Actions 기반 외부 리뷰봇이 상대인 경우가 많았고, 이 봇은 (1) 머지 OK
  신호를 발행하지 않아 신호를 기다리면 끝나지 않고, (2) push로만 재리뷰하며 대응 코멘트로는
  깨지 않고, (3) 매 라운드 새 Minor를 만들고 같은 코드의 평가가 뒤집히며, (4) diff 밖 설정이나
  PR 파일 목록 일부를 놓친 오탐을 반복하면서도 (5) 실제 결함도 낸다.
- `payload/agents/review-killer/AGENT.md`
  - **리뷰어 구성**: 기본 리뷰어 1개(CONTEXT), 추가 Agent 리뷰어는 이번 요청에서 명시할 때만
    (직전 PR 구성 복사 금지). 여럿이면 같은 head의 전원 리뷰를 모아(첫 리뷰 뒤 2사이클 대기,
    미도착은 명시) 리뷰어 라벨을 붙인 통합 대응 코멘트 1건. 사람 코멘트는 라운드가 아니며 다음
    리뷰어 라운드 대응 때 미처리분을 함께 처리, 종료 조건 아님, 수렴 뒤 코멘트는 보고만.
  - **재리뷰 트리거**: CONTEXT `재리뷰 트리거` — `reply-comment` / `push-only`(+ 선택적 수동
    재실행 수단). push-only면 커밋 없는 대응 코멘트로는 다음 라운드가 오지 않음을 전제로 판단.
  - **외부 리뷰봇 모드 — 수렴 판정**: Blocker 0 + Major 0 + 새로운 실질 지적 0 (+ CI green,
    머지 충돌 없음), 또는 근거 있는 반박에도 같은 지적이 3라운드 이상 반복되면 수렴. 봇의 실제
    결함은 기계적으로 반박하지 않는다. 최종 보고에 "머지 OK 신호 아님"과 근거 명시.
  - **오탐 처리**: head 파일·PR 파일 목록 API로 대조 후 수용, 인용된 프로젝트 규칙의 실재 확인,
    제안 명령·값은 검증 후 채택, 등급 상향만으로는 새 근거 아님, 리뷰어 제안이 더 나으면 반박
    철회, 낡은 PR 본문이 지적을 만들면 본문 먼저 갱신.
  - 종료 판정 2번을 "수렴"(무한 루프 수렴 + 외부 리뷰봇 수렴)으로 넓혔다. 종료 사유는 여전히 3가지.
- `payload/agents/reviewer/AGENT.md`: 오탐 방지(파일 목록·head 파일 확인, 규칙 인용은 실재
  `경로:줄`, 검증한 제안만), 판정은 PR 본문이 아니라 head 코드와 실제 CI로, 근거 없는 등급 상향
  금지·반박이 옳으면 철회. 다른 리뷰어·사람 코멘트로 인한 개수 증가는 대응이 아니므로 새 라운드를
  만들지 않는다.
- `payload/runtime/CONTEXT.md` 템플릿: `리뷰어 구성`, `재리뷰 트리거` 추가, `리뷰봇 식별자`를
